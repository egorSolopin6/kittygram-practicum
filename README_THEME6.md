# Тема 6 — «Кот дня»

Расширение Kittygram на Django REST Framework. Пользователи выбирают кота дня;
сервер ведёт дневные результаты и рейтинг за семь календарных дат.
Запуск, демонстрационные пользователи и Docker Desktop: [README](README.md), [DOCKER](DOCKER.md).

## Модели

| Модель | Назначение | Поля и связи | Ограничения |
|---|---|---|---|
| Cat | Кот и его владелец | name, color, birth_year, owner → User | Год 1900…текущий или null; owner назначает сервер |
| DailyTop | Результат кота за дату | date, cat → Cat, score | unique(date, cat); score ≥ 0, вычисляется из голосов |
| Vote | Выбор пользователя | user → User, daily_top → DailyTop, date, created_at | unique(user, date) |

У исходных записей без владельца `owner=null`; назначить владельца им может
администратор через админку. Рейтинги защищены от удаления связями `PROTECT`.

## Роли и ограничения

| Действие | Гость | Владелец | Наблюдатель | Участник голосования | Администратор |
|---|---|---|---|---|---|
| Публичная витрина, кот дня, топ недели | Да | Да | Да | Да | Да |
| Личные данные котов | Нет | Только свои | Только свои | Нет | Все |
| Создание, изменение, удаление котов | Нет | Только свои | Нет | Нет | Все |
| Голосование / отзыв своего голоса | Нет | Да | Нет | Да | Да |
| История своих голосов | Нет | Да | Да | Да | Только свои |
| Управление пользователями и группами | Нет | Нет | Нет | Нет | Да |

Роли реализованы группами Django: «Владельцы котов», «Наблюдатели»,
«Участники голосования». Группы создаёт команда `setup_roles` при запуске.
В API проверяются модельные разрешения и владелец объекта. Queryset в API
и админке ограничен текущим пользователем; чужая личная запись возвращает 404.
`is_staff` разрешает вход в админку, но не отменяет проверку владельца.
Полный доступ ко всем котам имеет только `is_superuser`.

Витрина публикует **только id, name, color**. Это отдельное представление для
голосования; в ней нет владельца и года рождения. Дневные результаты и голоса
в админке доступны для чтения; баллы нельзя вручную изменить даже администратору.

Для нового владельца администратор создаёт пользователя в `/admin/auth/user/`,
назначает группу «Владельцы котов» и включает «Статус персонала», если нужен
вход в админку. Для наблюдателя назначается группа «Наблюдатели». Флаг
«Статус суперпользователя» нужен только администратору. Кота новому пользователю
можно назначить в форме кота от имени администратора.
Открытой регистрации нет.

## Бизнес-правила и валидации

1. Один голос пользователя за календарную дату. Повторный POST — 400; сначала
   нужно отозвать предыдущий выбор. Ограничение есть и на уровне базы.
2. Голосование принимает только пустое тело или `{}`. Пользователь, дата и баллы
   определяются сервером; попытка передать `score` или `date` возвращает 400.
3. DELETE отзывает только собственный сегодняшний голос за указанного кота.
   Голоса другого пользователя или прошлых дат удалить через API нельзя.
4. Год рождения от 1900 до текущего или null — проверяется и в API, и в админке.
5. Фильтры дат требуют YYYY-MM-DD; будущие даты возвращают 400.
6. Кота с историей рейтинга нельзя удалить — 400 в API, защищённое удаление в админке.

Дата определяется в `Europe/Moscow`. Скор меняется вместе с голосом в транзакции
с выражением `F`. При равенстве баллов выше кот с меньшим ID. Кот дня без голосов
возвращает 404. Неделя — семь дат от `end_date - 6` до `end_date` включительно;
пустая неделя возвращает список с кодом 200.

## API-контракт

База: `http://localhost:8000`. Аутентификация: `Authorization: Token <token>`;
также поддерживаются Session и Basic. Вход в браузере — `/api-auth/login/`.

| Метод | URL | Доступ / назначение | Коды |
|---|---|---|---|
| POST | `/api/auth/token/` | username/password → token | 200, 400 |
| GET | `/api/cats/` | Свои коты; для администратора все | 200, 401, 403 |
| GET | `/api/cats/mine/` | Свои коты для любой роли с view_cat | 200, 401, 403 |
| POST | `/api/cats/` | Владелец или администратор; создать своего кота | 201, 400, 401, 403 |
| GET | `/api/cats/{id}/` | Владелец, наблюдатель или администратор | 200, 401, 403, 404 |
| PUT/PATCH | `/api/cats/{id}/` | Владелец своего кота или администратор | 200, 400, 401, 403, 404 |
| DELETE | `/api/cats/{id}/` | Владелец или администратор, без рейтинга | 204, 400, 401, 403, 404 |
| GET | `/api/showcase/cats/` | Публичная витрина | 200 |
| GET | `/api/showcase/cats/{id}/` | Публичная карточка | 200, 404 |
| POST | `/api/cats/{id}/vote/` | Владелец / участник / администратор; голос сегодня | 201, 400, 401, 403, 404 |
| DELETE | `/api/cats/{id}/vote/` | Те же роли; отозвать свой сегодняшний голос | 204, 401, 403, 404 |
| GET | `/api/showcase/day/` | Кот дня, необязательный date | 200, 400, 404 |
| GET | `/api/showcase/daily/` | Дневные результаты | 200, 400 |
| GET | `/api/showcase/daily/{id}/` | Один дневной результат | 200, 404 |
| GET | `/api/showcase/week/` | Недельный рейтинг, необязательный end_date | 200, 400 |
| GET | `/api/showcase/my-votes/` | Только свои голоса | 200, 400, 401 |
| GET | `/health/` | Проверка работы | 200 |

Для всех пагинированных списков несуществующая страница возвращает 404.
`/cats/` — совместимый маршрут GET/POST с теми же правами и пагинацией, что
`/api/cats/`. Корневой URL открывает админку.

## Примеры JSON

Вход:

```http
POST /api/auth/token/
Content-Type: application/json

{"username":"anna","password":"<DEMO_PASSWORD из .env>"}
```

Ответ 200: `{"token":"<token>"}`. Затем передайте заголовок
`Authorization: Token <token>`.

Создание своего кота:

```http
POST /api/cats/
Content-Type: application/json
Authorization: Token <token>

{"name":"Барсик","color":"gray","birth_year":2024}
```

Пример ответа 201 (ID зависят от базы):

```json
{"id":15,"name":"Барсик","color":"gray","birth_year":2024,"owner":2}
```

| Запрос | Тело | Пример ответа |
|---|---|---|
| GET `/api/cats/15/` | — | 200: объект кота выше |
| PATCH `/api/cats/15/` | `{"color":"black"}` | 200: объект с новым цветом |
| DELETE `/api/cats/15/` | — | 204, пустое тело, если кот не участвует в рейтинге |
| GET `/api/cats/15/` от другого владельца | — | 404: `{"detail":"Не найдено."}` |
| PATCH `/api/cats/{id}/` от viewer | `{"color":"black"}` | 403, нет прав на изменение |
| GET `/api/showcase/cats/4/` | — | 200: `{"id":4,"name":"Луна","color":"black"}` |
| POST `/api/cats/4/vote/` | `{}` | 201: id, date, cat_id, cat_name, created_at |
| Повторный POST голосования | `{}` | 400: `{"vote":"Вы уже голосовали сегодня. Сначала отзовите предыдущий голос."}` |
| DELETE `/api/cats/4/vote/` | — | 204 при наличии своего голоса сегодня |
| GET `/api/showcase/day/` | — | 200: id, date, cat: {id, name, color}, score |
| GET `/api/showcase/daily/1/` | — | 200: тот же формат дневного результата |
| GET `/api/showcase/week/` | — | 200: count, next, previous, results: [{rank, cat_id, name, color, score}], date_from, date_to |
| GET `/api/showcase/my-votes/` | — | 200: count, next, previous, results со своими голосами |
| GET `/api/showcase/day/?date=2099-01-01` | — | 400: `{"date":"Дата не может быть в будущем."}` |

Передача owner при создании/изменении через API игнорируется: поле только для чтения.
Назначать другого владельца может администратор через админку.

## Фильтры и пагинация

По умолчанию 5 записей, максимум 100. Параметры `page`, `page_size`;
формат ответа `count`, `next`, `previous`, `results`.

- `/api/cats/?color=black&search=Луна&page_size=1` — только среди доступных котов.
- `/api/showcase/cats/?search=Луна` — поиск в публичной витрине.
- `/api/showcase/daily/?date=2026-10-26&cat=4&page_size=1` — дата и кот.
- `/api/showcase/week/?end_date=2026-10-26&color=black&page_size=1` — семь дат по 26 октября.
- `/api/showcase/my-votes/?date=2026-10-26&cat=4` — только свои голоса.

## Демонстрационные данные

Команда `seed_showcase` создаёт 12 котов, 16 пользователей и историю голосов за
семь дат: 12 голосов в каждую из предыдущих шести дат и 10 за сегодня.
Это учебная история, добавленная командой наполнения. Имеющиеся записи и голоса
не удаляются; поэтому в перенесённой базе количество может быть больше.
Повторный запуск в ту же дату не создаёт дублей. Счёт пересчитывается по Vote.

## Проверка

[Postman-коллекция](Kittygram-theme6.postman_collection.json) проверяет вход,
голосование, CRUD и ограничения ролей. Задайте `demo_password` из `.env`.
Прогон создаёт и удаляет временного кота, отзывает текущий голос anna и оставляет
голос за Луну. Пароль и токены в коллекцию не включены.

```sh
docker compose exec web python manage.py check
docker compose exec web python manage.py makemigrations --check --dry-run
docker compose exec web python manage.py test showcase --verbosity 2
```

22 теста проверяют доступ к своим/чужим котам, запрет обхода через старый URL,
различие staff/superuser, права наблюдателя и участника голосования, защиту
админки, подмену владельца, валидации, историю голосов, уникальность, рейтинги,
пагинацию и вход по токену. Тесты используют отдельную временную базу.
